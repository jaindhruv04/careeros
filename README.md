# CareerOS

CareerOS is a full-stack placement-preparation dashboard for students. It brings DSA tracking, job application tracking, interview notes, project planning, progress analytics, and an AI assistant into one application.

**Live application:** https://careeros-dwui.onrender.com  
**Backend API:** https://careeros-api-0zqj.onrender.com  
**Repository:** https://github.com/jaindhruv04/careeros

## Features

### Dashboard
- Combined overview of company applications, DSA problems, interview entries, and projects.
- High-priority items across the trackers.
- Progress summaries, recent activity, and quick insights derived from tracker data.
- Daily goals checklist. Goals are held in component state and reset when the page is refreshed.

### DSA tracker
- Create, view, edit, and delete DSA problem records.
- Store topic, difficulty, status, priority, revision flag, and notes.
- Archive and restore problems.
- Search and filter the problem list.
- Persist records in PostgreSQL through the Express API.

### Company application tracker
- Create, view, edit, and delete company application records.
- Store company name, role, application status, application date, priority, and notes.
- Archive and restore applications.
- Search and filter application records.
- Persist records in PostgreSQL through the Express API.

### Interview journal
- Record company, interview round, questions asked, personal answers, mistakes, lessons learned, and priority.
- Edit, delete, archive, and restore interview entries.
- Search and filter entries.
- Store entries in browser `localStorage`.

### Project tracker
- Track project name, technology stack, progress percentage, status, priority, and notes.
- Edit, delete, archive, and restore project entries.
- Search and filter projects.
- Store entries in browser `localStorage`.

### Analytics
Analytics are generated by the backend from the authenticated user's **non-archived DSA problems and company applications**.

DSA analytics include:
- Total, solved, in-progress, and not-started problem counts.
- Overall solve rate and solve rate by difficulty.
- Difficulty distribution.
- Topics with comparatively lower and higher solve rates.
- Problems flagged for revision.
- Solved-problem counts over the last 7 and 30 days, plus daily averages.

Company analytics include:
- Application counts and status/priority distributions.
- Interview and offer conversion calculations.
- Applications created in the last 30 days and daily average.

The analytics endpoint also returns rule-based insights and recommendations. Interview and project entries are not included in these backend analytics.

### CareerOS AI
CareerOS AI is a Groq-powered assistant available inside the authenticated dashboard.

It can use backend tools to:
- Read the current user's active company applications.
- Read the current user's active DSA problems.
- Create a DSA problem.
- Delete a DSA problem.

Available tools:

```text
get_my_companies
get_my_dsa_problems
create_dsa_problem
delete_dsa_problem
```

The backend executes these operations using Prisma. The model does not receive database credentials or direct database access. The user ID passed to each tool comes from the verified JWT in the backend request, not from model-generated input.

The assistant supports multiple tool-call rounds, with a maximum of five rounds per request. The current chat UI sends the latest message to the backend; the backend builds a new message context for each request, so chat history is not persisted server-side.

## Architecture and data flow

### Backend-persisted data

DSA problems and company applications are stored in PostgreSQL. Frontend requests include the JWT as a Bearer token.

```text
React page / context
        |
        v
apiFetch() + Bearer JWT
        |
        v
Express route
        |
        v
JWT authentication middleware
        |
        v
Controller
        |
        v
Prisma ORM
        |
        v
PostgreSQL
        |
        v
JSON response -> React state -> UI
```

### Browser-persisted data

Interview journal entries and project tracker entries are stored in browser `localStorage` using React reducers and effects. They are not currently synchronized with the backend or available across devices.

Daily goals are held in the Dashboard component's React state and are not persisted.

### AI tool execution

```text
Authenticated user message
        |
        v
POST /ai/chat
        |
        v
JWT middleware -> req.userId
        |
        v
Groq chat completion
        |
        v
Model requests an available tool
        |
        v
Backend tool implementation
        |
        v
Prisma query scoped to req.userId
        |
        v
Tool result returned to Groq
        |
        v
Assistant reply
```

## Authentication

- Registration hashes passwords with bcrypt before storing user records.
- Login verifies the password and returns a JWT.
- The JWT contains the user's ID and expires after seven days.
- The frontend stores the token in browser `localStorage`.
- Protected API requests send the token using the `Authorization: Bearer <token>` header.
- Backend middleware verifies the token and attaches the authenticated user's ID to `req.userId`.
- DSA and company database queries are scoped to the authenticated user.

## API routes

All routes are mounted by the Express application. Routes marked **Protected** require a valid Bearer JWT.

| Method | Endpoint | Description | Access |
|---|---|---|---|
| POST | `/users/register` | Register a user | Public |
| POST | `/users/login` | Log in and receive a JWT | Public |
| POST | `/users/logout` | Return logout confirmation | Public |
| GET | `/users/me` | Get the authenticated user's basic profile | Protected |
| GET | `/dsa` | List the user's DSA problems | Protected |
| POST | `/dsa` | Create a DSA problem | Protected |
| GET | `/dsa/:id` | Get one of the user's DSA problems | Protected |
| PATCH | `/dsa/:id` | Update a DSA problem | Protected |
| DELETE | `/dsa/:id` | Delete a DSA problem | Protected |
| GET | `/companies` | List the user's company applications | Protected |
| POST | `/companies` | Create a company application | Protected |
| GET | `/companies/:id` | Get one of the user's applications | Protected |
| PATCH | `/companies/:id` | Update a company application | Protected |
| DELETE | `/companies/:id` | Delete a company application | Protected |
| GET | `/analytics` | Get DSA and company analytics | Protected |
| POST | `/ai/chat` | Send a message to CareerOS AI | Protected |

## Database models

The Prisma schema currently defines three PostgreSQL models:

- **User:** email, optional name, password hash, creation timestamp, and relations to DSA problems and company applications.
- **DSAProblem:** name, topic, difficulty, status, priority, revision flag, optional notes, archive flag, timestamps, and owning user ID.
- **Company:** name, role, status, optional application date, priority, optional notes, archive flag, timestamps, and owning user ID.

Deleting a user cascades to their related DSA problem and company records.

## Run locally

### Prerequisites
- Node.js and npm
- A PostgreSQL database
- A Groq API key for CareerOS AI

### 1. Clone the repository

```bash
git clone https://github.com/jaindhruv04/careeros.git
cd careeros
```

### 2. Configure the backend

Create `server/.env`:

```env
DATABASE_URL=your_postgresql_connection_string
JWT_SECRET=your_jwt_secret
GROQ_API_KEY=your_groq_api_key
GROQ_MODEL=openai/gpt-oss-20b
CLIENT_ORIGIN=http://localhost:5173
PORT=3000
```

`GROQ_MODEL` is optional; the backend defaults to `openai/gpt-oss-20b`.

Install dependencies and start the backend:

```bash
cd server
npm install
npx prisma generate
npx prisma migrate deploy
node app.js
```

For a new local database where migrations have not yet been applied, use the Prisma migration workflow appropriate to your development setup before starting the server.

### 3. Configure the frontend

In the repository root, create a `.env` file:

```env
VITE_API_URL=http://localhost:3000
```

In a second terminal:

```bash
npm install
npm run dev
```

Vite prints the local frontend URL in the terminal, normally http://localhost:5173.

## Available frontend scripts

Run these from the repository root:

| Command | Purpose |
|---|---|
| `npm run dev` | Start the Vite development server |
| `npm run build` | Build the frontend for production |
| `npm run preview` | Preview the production build locally |
| `npm run lint` | Run Oxlint |
| `npm run deploy` | Publish the built `dist` directory using gh-pages |

The backend package provides an integration-test command. Start the API with `node app.js` after installing dependencies and configuring the environment.

### Backend integration tests

Run the integration tests from `server/`:

```bash
npx prisma migrate deploy
npm test
```

The tests use Node.js's built-in test runner and the existing PostgreSQL driver. They start the Express API, exercise authentication and protected API routes, verify DSA and company CRUD plus per-user access isolation, and check the analytics response.

**Important:** The test setup truncates the `User`, `DSAProblem`, and `Company` tables before running. Set `DATABASE_URL` to a dedicated test database only. Never point the test command at development or production data.

GitHub Actions runs the same tests against a fresh PostgreSQL service on relevant pushes and pull requests.

## Current limitations

- DSA problems and company applications are persisted in PostgreSQL; interview journal and project tracker data are stored only in the current browser's `localStorage`.
- Daily goals are component state only and reset when the Dashboard is refreshed.
- Interview and project data are not included in backend analytics.
- AI tools currently support reading company and DSA records, plus creating and deleting DSA records. They do not create or modify company applications.
- AI-triggered DSA changes are made in the database, but the DSA context is not automatically refreshed by the AI chat component. Refreshing the tracker data is needed to see those changes in its list.
- The AI chat interface does not persist conversation history between page reloads or send its history for backend context.
- Automated integration tests cover the authenticated REST API. The Groq provider integration and browser-only interview, project, and daily-goal flows do not currently have automated test coverage.
